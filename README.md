# Mission Health

Прототип команды для задания NASA Space Apps 2026: ПО собирает показатели здоровья и помогает астронавтам оценивать состояние и принимать меры. Панель показателей, сравнение с личной базовой линией, дневник и поиск по истории - предложенная командой реализация.

## Интерфейс

- Liquid Glass, светлая и темная темы с зеленой палитрой.
- Английский, китайский, арабский и испанский языки; арабский интерфейс справа налево.
- Профили Jessica Meir, Jack Hathaway и Christina Koch с официальными фото и ссылками NASA.
- Графики за 1 минуту, 1 час, 24 часа, 7 дней, 1 месяц и 1 год.
- Отдельный дневник и чат для каждого профиля. Все показатели и сценарии демонстрационные; это не реальные медицинские данные этих людей.

## Хранение и поиск

Браузер отправляет сообщение серверу сайта. Сервер сохраняет оригинал в D1 и передает выбранную историю GPT-5.5 через ProxyAPI. Пользователь ищет записи обычным вопросом в чате; отдельного поля поиска нет. Сервер отбирает записи только нужного владельца и профиля, а источники раскрываются под ответом.

Локальная EmbeddingGemma 2 индексирует тексты в Qdrant векторами размерности 768. Когда сервис векторной памяти доступен, сервер использует семантический поиск и повторно проверяет найденные записи в D1. Без него облачный чат использует сохраненную историю и поиск по словам в последних 200 записях. Интерфейс различает подключенную историю и семантическую память. Для полностью локального запуска без ProxyAPI сохранен помощник Qwen3.

Записи сохраняются до индексации. Если память недоступна, запись остается в базе со статусом ожидания и индексируется после восстановления связи. Повторная отправка с тем же идентификатором не создает дубликат. Каждая новая запись запрашивает ответ. При сбое облачного сервиса запускается резервный помощник Qwen3.5-0.8B в браузерном воркере. Его первое использование скачивает около 720 МБ открытых весов; затем браузер использует кеш. Резервный ответ сохраняется на сервере и отдельно подписывается в чате. Кнопка повтора использует исходный идентификатор вопроса и не создает его копию. Enter отправляет сообщение, Shift+Enter добавляет строку. Надиктованный в поле текст отправляется тем же способом.

Сайт получает идентификатор пользователя только из доверенного заголовка платформы. `LOCAL_PREVIEW` задан исключительно в локальном конфиге. Ключ памяти хранится вне Git. Qdrant и сервис моделей слушают только `127.0.0.1`. Секрет не передается браузеру.

## Фото и видео

Камера и загрузка файлов доступны внутри дневника. Для каждого снимка или ролика выбирается лицо либо название участка кожи. Сравнение ограничено одним владельцем, профилем, названием участка и видом материала. Файлы хранятся в закрытом R2, метаданные и векторы в D1. Прямые запросы к файлам проходят проверку владельца; видео поддерживает частичное чтение для воспроизведения.

Отдельный браузерный Web Worker использует настоящую мультимодальную EmbeddingGemma 2 в ONNX q4. Фото преобразуется в нормализованный вектор из 768 чисел. Видео до 15 секунд и 20 МБ разбирается на не более 12 кадров, из которых модель создает один вектор ролика. В R2 остается оригинальный ролик и три кадра для просмотра помощником. Запись с камеры не включает микрофон; звук загруженного видео не анализируется. Первое использование модели скачивает около 290 МБ весов, повторное использует кеш браузера. Воркер может использовать WebGPU или WASM.

Для текущего материала сравниваются до 200 предыдущих записей с точно такой же версией модели и способом обработки. Интерфейс показывает ближайший по косинусному сходству материал и отдельно дает доступ к последнему по времени. Если вектора еще нет, доступно сравнение по дате и повтор индексации. История показывает также загруженные материалы, еще не отправленные в чат. Для чата GPT получает три кадра каждого выбранного ролика; при сбое API резерв показывает серверные даты и результат сравнения векторов без визуальных или медицинских выводов.

Сходство эмбеддингов применяется для подбора истории, не является медицинским показателем. Это прототип визуального дневника без клинической проверки. Он не обнаруживает рак, не исключает опасность родинки и не измеряет пульс, дыхание или походку по видео. Нужны одинаковые ракурс, освещение и масштаб. Изменяющаяся, растущая, зудящая или кровоточащая родинка требует осмотра врача.

На опубликованном сайте векторы фото и видео сохраняются в D1; локальный Qdrant используется для текстовой памяти и не подключен к облачному сайту. Сравнение запускается при новой загрузке, постоянного фонового наблюдения за камерой нет.

## Сценарии демонстрации

1. Сон: сохранить запись о продолжительности сна, уровне энергии и двух пробуждениях из-за вентилятора. Затем спросить, что мешало сну. Помощник находит запись и указывает дату.
2. Нагрузка: записать самочувствие после тренировки. Через несколько записей спросить, какие наблюдения повторяются после активности.
3. Визуальный дневник: выбрать один участок, загрузить снимок или короткий ролик, позднее повторить съемку. Открыть сравнение и спросить через чат о видимых различиях. Для ролика помощник обязан учитывать, что видел только выбранные кадры.
4. Итоги: попросить кратко вспомнить неделю и перечислить записи, на которых основан ответ. При недостатке записей помощник должен сообщить об этом.

Чипы в чате подставляют текст для редактирования; отправка выполняется пользователем. Дневники разных профилей не объединяются. Прототип не ставит диагнозы и не назначает лечение.

## Локальный запуск на Mac с Apple Silicon

Нужны Docker Desktop, Node.js и Python 3.12. Включите Docker Desktop. В каталоге проекта выполните:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r local/requirements.txt
.venv/bin/python local/download_models.py
npm ci
bash local/start.sh
```

Откройте `http://localhost:8765`. Первый запуск скачивает примерно 1.5 ГБ весов EmbeddingGemma 2 и отдельные веса Qwen3. Сервис памяти работает на порту 8091, Qdrant на 6333. Веса, базы, ключи и окружение исключены из исходников. Локальная база D1 находится в `.wrangler/state`, векторы в `local/storage/qdrant`.

Для остановки интерфейса и сервиса памяти нажмите Ctrl+C в терминале запуска. Для остановки Qdrant:

```bash
docker stop mission-health-qdrant
```

## Опубликованный сайт

Оригиналы дневников сохраняются в серверной D1. GPT-5.5 подключен через ProxyAPI; Mac может быть выключен. Параметры `LLM_BASE_URL`, `LLM_MODEL` и секрет `LLM_API_KEY` задаются в настройках Sites. Токен не включается в браузерные файлы, исходники и архивы.

Облачный сайт не обращается к локальному Mac через `localhost`. Для подключения именно локальной векторной памяти понадобится доступный сервер сервиса памяти. Сейчас такой канал не создается; поиск истории использует D1. Ответы идут через ProxyAPI, при его недоступности используется браузерный резерв. Конфигурация API сама по себе не подтверждает доступность провайдера.

Для сборки выполните `npm run build`. Генерируется Worker `dist/server/index.js`, манифест и миграции D1. Схема базы находится в `db/schema.ts`, миграции в `drizzle/`.

## Проверено

- Сохранение и индексация реальной локальной EmbeddingGemma 2 в Qdrant.
- Семантический поиск по формулировке, отличающейся от исходной записи.
- Изоляция владельцев и профилей, запрет доступа к сервису памяти без ключа.
- Повторная отправка без дубликатов.
- Реальный ответ GPT-5.5 через ProxyAPI с историей дневника без локального сервиса в предыдущей версии.
- В текущем сеансе ProxyAPI возвращает 503; проверен запуск браузерной Qwen3.5-0.8B. Из-за обнаруженных выдуманных визуальных различий эта модель применяется только к текстовому дневнику. Для фото и видео резервный ответ формируется из проверяемых серверных данных и отдельно подписывается как визуальная история.
- Настоящие 768-мерные векторы фото и видео в браузере, сохранение в D1, сравнение одинаковых роликов со сходством 1.000.
- Воспроизведение видео с частичными запросами 206, повторное открытие истории и запрет получения чужого файла 404.
- Отправка Enter и сохранение резервного ответа в D1.
